# Guide and Dressing Room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After a person approves their character sheet, Claude writes their personal style guide, and a virtual dressing room puts any of its outfits on them with Gemini, with every image downloadable.

**Architecture:** Same app and patterns as the foundation. Guide generation is a background job triggered by sheet approval, writing structured JSON to the profile row (guarded by its own `guide_attempt`). Try-ons live in a new `tryons` table, one row per generated image, each generated by a background job. The results page `/p/[id]` becomes the guide, with the dressing room as an outfit grid that opens a centered dialog.

**Tech Stack:** As foundation, plus `fflate` (zip for "Download all").

**Spec:** `docs/superpowers/specs/2026-10-25-style-file-app-design.md` (flow steps 7 and 8, Look and feel).

## Global Constraints

- Everything in the foundation plan's Global Constraints still applies (tokens, Archivo Narrow, no radius or shadows, terse uppercase copy, no em dashes, local only).
- No example images anywhere. Empty states are plain placeholders. Demo mode (no key) draws gray placeholders, never a real person.
- Claude model `CLAUDE_MODEL` (default `claude-sonnet-5-5`), structured output via `messages.parse` + `zodOutputFormat` with `zod/v4`. No forced tool calls.
- Gemini model `GEMINI_MODEL` (default `gemini-3-pro-image-preview`), request shape as `generateCharacterSheet`, aspect `3:4`, size `2K`.
- Try-on download filename: `<person>-<outfit>-<version>.<ext>` via `downloadName`. "Download all" zip: `<person>-dressing-room.zip`, latest version of each outfit.

## Review Focus

1. Approving a sheet twice, or retrying the sheet after approval: guide must not generate twice in parallel or be overwritten by an older run (guide_attempt guard).
2. Claude returns a store id not in the catalog or an invalid hex: the guide still renders (schema enum + fallback), never a 500.
3. Clicking "Try it on" repeatedly: each click is its own version; versions never overwrite each other.
4. Deleting a profile while a try-on is generating: no crash, no files recreated.
5. "Download all" with no try-ons yet: plain message, not an empty or broken zip.

### Task 1: Schema, catalog and guide types

**Files:** Create `app/db/migrations/002_guide_tryons.sql`, `app/src/lib/stores.ts`, `app/src/lib/guide.ts`; Modify `app/src/lib/profiles.ts`. Test `app/tests/guide.test.ts`, extend `app/tests/profiles.test.ts`.

**Interfaces:**
- Migration: `profiles` gains `guide jsonb`, `guide_status text not null default 'none'`, `guide_error text`, `guide_attempt integer not null default 0`, `capsule_owned jsonb not null default '[]'`. New table `tryons(id text primary key, profile_id text not null references profiles(id) on delete cascade, outfit_id text not null, version integer not null, prompt text not null, path text, status text not null default 'pending', error text, created_at timestamptz not null default now(), unique(profile_id, outfit_id, version))`.
- `STORES: Record<StoreId, { name: string; url: string; tier: '$'|'$$'|'$$$'; sections: ('mens'|'womens')[]; note: string }>`: the 16 stores from the root `index.html` `STORES` (all `['mens']` except Uniqlo, J.Crew, Banana Republic, Everlane, Nordstrom, L.L.Bean, Lands' End, Huckberry which are both), plus women's: `madewell` (Madewell, $$), `aritzia` (Aritzia, $$), `cos` (COS, $$), `reformation` (Reformation, $$$), `quince` (Quince, $), `vince` (Vince, $$$), `sezane` (Sézane, $$$), `gap` (Gap, $), each `['womens']` or both where they sell both. `STORE_IDS` tuple of keys.
- `GuideSchema` (zod v4): `{ summary: string; families: [{ name, purpose, swatches: [{ name, hex /^#[0-9A-Fa-f]{6}$/ }] x4 }] x3; fitRules: [{ title, body }] 3–5; stylingRules: [{ title, body }] 3–5; capsule: [{ item, category }] 12–20; outfits: [{ id /^o\d{2}$/, name, occasion: 'Work'|'Weekend'|'Evening'|'Travel', season: 'Spring'|'Summer'|'Fall'|'Winter'|'All year', setting, why, pieces: [{ item, color, hex, fabric, search, stores: StoreId[] 1–2 }] 3–5 }] exactly 12 }`. `type Guide`.
- `guidePrompt(p: Profile): string`: builds the request from answers (labels, not codes), coloring, climate, budget tier and the store ids allowed for their section and budget.
- Profile gains `guide: Guide | null`, `guideStatus`, `guideError`, `guideAttempt`, `capsuleOwned: number[]`. New repo functions: `beginGuide(id): Promise<number>` (bumps `guide_attempt`, status `pending`), `finishGuide(id, attempt, r: { guide: Guide } | { error: string }): Promise<boolean>` (attempt-guarded), `setCapsuleOwned(id, owned: number[]): Promise<void>`.

**Interfaces:**
- `generateGuide(p: Profile, photo: Buffer): Promise<Guide>`: live = `messages.parse` with the photo + `guidePrompt(p)`, `max_tokens: 16000`, `output_config: { effort: 'medium', format: zodOutputFormat(GuideSchema) }`; throws `Error('THE GUIDE DIDN'T COME BACK. TRY AGAIN.')` on refusal or null parse. Demo = `DEMO_GUIDE` (a valid 12-outfit guide built from neutral pieces, using the original guide's outfits as the source of variety).

- Approve: after `approveSheet`, `startGuideJob(id, await beginGuide(id))` unless `guideStatus` is `pending` or `ready`. Regenerate: `POST` → `beginGuide` + start, `303` to `/p/<id>`.
- Status JSON adds `guideStatus`, `guideError`.

- [ ] Tests (mock `generateGuide`): job success stores the guide and `ready`; failure stores the message; stale attempt dropped; approve twice starts one job; regenerate bumps attempt.

### Task 4: Try-on generation

**Files:** Create `app/src/lib/tryons.ts`, `app/src/lib/ai/tryon.ts`; Modify `app/src/lib/jobs.ts`, `app/src/lib/ai/demo-sheet.ts` (export a try-on placeholder); Create `app/src/pages/api/p/[id]/tryons/index.ts` (GET list, POST start), `app/src/pages/api/p/[id]/tryons/[tid].ts` (GET image, `?download=1`), `app/src/pages/api/p/[id]/tryons/zip.ts`. Test `app/tests/tryons.test.ts`.

**Interfaces:**
- `type Tryon = { id, profileId, outfitId, version, prompt, path: string|null, status: JobStatus, error: string|null, createdAt }`. `createTryon(profileId, outfitId, prompt): Promise<Tryon>` (next version per outfit, in one statement), `listTryons(profileId): Promise<Tryon[]>`, `finishTryon(id, r: {path}|{error}): Promise<boolean>`.
- `tryonPrompt(p: Profile, outfit: Outfit): string`: modeled on the original `buildPrompt`, but generic: "the person in the attached character sheet", keep face, glasses if any, hair, facial hair, skin tone, height, build and tattoos; full-body three-quarter view in the outfit's pieces (color, item, fabric); setting from the outfit; fit rule "tailored, not tight" adjusted by their fit goals; no text/logos/watermark; one image.
- `generateTryon(sheet: Buffer, prompt: string): Promise<Buffer>` (Gemini; demo = gray placeholder figure, 1200x1600).
- `runTryonJob(tryonId)`: reads the profile's approved sheet; if the profile or row is gone at save time, writes nothing.
- `POST /api/p/[id]/tryons` JSON `{ outfitId, prompt? }` → 409 unless sheet approved and guide ready; 400 for unknown outfit; else creates row, starts job, returns the row. `GET` → `{ tryons: Tryon[] }`.
- Zip: latest ready try-on per outfit, filenames via `downloadName(person, outfitName, version, ext)`; none ready → 404 JSON `{ error: 'NO TRY-ONS YET.' }`.

- [ ] Tests (mock `generateTryon`): two POSTs for one outfit make versions 1 and 2; job stores path and `ready`; failure stores message; deleted profile mid-flight writes nothing; zip with none ready → 404; zip with two ready outfits contains two correctly named entries; POST before approval → 409.

### Task 5: Dressing room dialog

**Files:** Create `app/src/components/OutfitDialog.astro`; Modify `app/src/pages/p/[id]/index.astro`.

**Interfaces:** Clicking an outfit card opens a centered `<dialog>` (same style as the questionnaire pop-up): left = large 3:4 image (selected version or palette stack) with version thumbnails below; primary `TRY IT ON` (or `TRY ANOTHER`), `DOWNLOAD` for the shown version, collapsible `EDIT THE PROMPT` textarea (sent with the POST); right = pieces list (swatch, item in color, fabric, store links in navy, Google Shopping and Amazon search links) and a `WHY IT WORKS` block. While a version is pending, its thumbnail shows a `--chip` placeholder and the dialog polls `GET /tryons` every 3 s. The grid card updates to the newest ready image. Header of the dressing room has `DOWNLOAD ALL`.
